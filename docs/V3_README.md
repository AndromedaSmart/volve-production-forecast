# Volve v3: прямые горизонты, история против oracle

Отдельная ветка расчёта. Модули v1/v2 не изменены; результаты v2 (Арпс, LightGBM, Transformer, CSDI, нефть×ГФ) в v3 не пересчитывались.

Запуск: `python volve_v3.py --data data/data.xlsx --out reports/v3` (нужны numpy, pandas, scikit-learn, openpyxl).

## Метод
- Шесть отдельных Ridge-моделей по горизонтам 1..6, без рекурсии, без линейного индекса времени.
- Признаки: лаги 1/2/3/6, средние 3/6, стандартное отклонение 6; нормировка уровнем последних 6 месяцев на дате происхождения.
- Выбор среди mean6/median6/last/Ridge/Ridge+log1p(вода/нефть), alpha 1/10/100 только по внутренним отсечениям -6/-12/-18 месяцев; минимум 18 месяцев. При отсутствии фолдов (окно 1) — заранее заданное mean6.
- Скважинная сумма по стволам с >=6 известными месяцами; оценка против полного факта месторождения.
- Будущие фактические часы только в отдельном oracle-сценарии; архивного плана нет.

## Ограничения
- Пять окон уже изучались при разработке: оценка ретроспективная, не новый независимый тест. Скважинная медиана не является независимо подтверждённым победителем.
- Физический признак нестабилен; универсальный выигрыш не подтверждён.
- Oracle: у F-1 C нет часов за май-июнь 2016, WAPE окна 5 и RMS по пяти окнам не определены; пропуски не заменялись нулями.
- Новые стволы (окно 3) и F-5 (окно 5) не покрыты скважинным прогнозом.
- Графики, Word и Excel в репозиторий не добавлены (бинарные файлы); формируются отдельным шагом отчёта.
